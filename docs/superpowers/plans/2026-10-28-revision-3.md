# Revision 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Use all of switching's and tracking's data, add a tracking-switching part, make the four parts equal with handover cues and a big timer, and cut "change by luck" to ≤1%.

**Architecture:** Every change to measurement, scoring, steering and the A/B rule lives in the pure core (`src/core`) and is unit-tested. Switching reuses the flick metric pipeline: each switch becomes a `TrialMetrics`. Tracking switching gets its own runner, measure and simulator model, built on a generalised moving-target path. The UI adds a `cue` phase to the run controller.

**Tech Stack:** TypeScript strict, Vite, Vitest, Preact, three.js.

**Spec:** `docs/superpowers/specs/2026-10-27-blind-sens-finder-design.md` §17 (read §16 for context).

## Global Constraints

- Parts are 14 s each (quick: 8 s), with lead-ins inside the part. The handover cue is 1.8 s, with ticks 600 ms apart.
- Score weights: flick 0.3, switch 0.25, tracking 0.25, trackswitch 0.2.
- Tracking-switching settings:
  - 3 targets, radius 2°, 0.7 s health
  - region ±35° yaw / ±15° pitch, speeds 10–25 °/s
  - lead-in 1.5 s (quick 1 s)
- A/B rule: z = 2.5, and "change" only at look 2, with look 1's δ > 0.
- Never output a per-axis sens. Per-axis figures are for diagnosis only.
- Every tunable lives in `src/core/config.ts`. The core never imports DOM, three or preact.
- Never loosen a stats-suite threshold. If one fails, stop and report it to the user.
- Warm-up stays optional. Misclicks keep the current game behaviour; they are measurement data only.

## Review Focus

1. **A part with almost no data:** a switching part where only warm-in kills happen, a tracking part where the button is never held, or a trackswitch part with no kills. Every summary field must be finite (no NaN). Nullable gains stay null, and the session retries once.
2. **Old history entries:** steps saved before this revision lack the `trackSwitch` and new metric fields. They must still render in History and Results without crashing.
3. **The player declines the confirmation round while ahead:** the verdict must be "none", never "change".
4. **Esc during a handover cue:** this pauses the run. Resuming restarts the cue, and the next part's timing and the data recorded so far are unchanged.
5. **Two trackswitch targets on top of each other:** damage goes to only one target (the nearest), so the kill count can never double.
